[64] 摘  要
[65] 我国自然灾害频发，地震、洪涝、台风等灾害每年造成大量人员伤亡和财产损失。灾后临时安置点在供水、供电保障与环境安全管理方面长期面临人工巡检效率低、数据分散、异常响应滞后等突出问题。针对上述问题，本文设计并实现了一套面向灾后临时安置点的智慧水电管理与环境监测系统。系统采用"云、边、端"协同的物联网三层架构：STM32嵌入式终端负责多源传感器数据采集与执行器控制；ESP32作为边缘网关完成WiFi接入、MQTT协议通信与本地阈值判断；上位机桌面应用基于Qt 6.11框架开发，提供实时监控、历史查询、报警管理与远程控制功能；Web大屏基于ECharts5.5.1实现可视化仪表盘。系统综合运用DHT11温湿度传感器、GP2Y1014AU0F粉尘传感器、MQ-135空气质量传感器、ACS712ELCTR-05B电流传感器与霍尔水流传感器，实现了对安置点温度、湿度、PM2.5、空气质量、用电电流及水流量的实时监测。系统还集成了SG90舵机、直流风扇、有源蜂鸣器与RGB指示灯等执行机构，可根据环境参数自动调节通风、散热与报警状态。系统实现了三级报警与预警机制，确保异常情况及时响应。测试结果表明，系统运行稳定，传感器数据采集准确，MQTT通信可靠，报警响应时间不超过3秒，能够有效满足灾后安置点水电管理与环境监测的实际需求，具有重要的应用推广价值。

[83] ABSTRACT
[84] Natural disasters occur frequently in China, causing massive casualties and economic losses each year. Post-disaster temporary resettlement sites have long faced challenges in water supply, power supply, and environmental safety management, including low manual inspection efficiency, fragmented data, and delayed anomaly response. To address these issues, this thesis designs and implements a smart water-electricity management and environmental monitoring system for post-disaster temporary shelters. The system adopts a "cloud-edge-device" collaborative IoT three-tier architecture: an STM32 embedded terminal collects multi-sensor data and controls actuators; an ESP32 edge gateway provides WiFi connectivity, MQTT protocol communication, and local threshold decision-making; a Qt 6.11-based desktop application offers real-time monitoring, historical query, alarm management, and remote control; and a web-based dashboard using ECharts 5.5.1 provides real-time data visualization. The system integrates DHT11 temperature/humidity sensor, GP2Y1014AU0F dust sensor, MQ-135 air quality sensor, ACS712ELCTR-05B current sensor, and hall-effect water flow sensor to achieve real-time monitoring of temperature, humidity, PM2.5, air quality, electrical current, and water flow. A three-level alarm mechanism ensures timely response to abnormal conditions. Test results demonstrate stable system operation, accurate sensor data acquisition, reliable MQTT communication, and alarm response within 3 seconds, effectively meeting the practical requirements of post-disaster shelter management with significant application value.

[156] 第1章 绪论
[157] 1.1 研究背景与意义
[158] 我国是世界上自然灾害最为严重的国家之一，地震、洪涝、台风等灾害频发，每年造成大量人员伤亡和财产损失。灾害发生后，大量受灾群众需要转移至临时安置点进行过渡性安置。灾后临时安置点的供水、供电保障与环境安全管理直接关系到受灾群众的基本生活保障和生命健康安全，是灾后应急响应与恢复重建工作的重要环节。
[159] 传统的安置点管理模式主要依赖人工巡检和纸质记录，存在以下突出问题：（1）巡检效率低下，人工无法实现全天候不间断监测；（2）数据分散，缺乏统一的信息化管理平台，难以形成有效的决策支持；（3）异常响应滞后，水电泄漏、环境恶化等安全隐患难以及时发现和处置；（4）缺乏智能化调控手段，无法根据环境变化自动调节通风、散热等设备。这些问题严重制约了安置点管理水平的提升，亟需引入信息化、智能化技术手段加以解决。
[160] 近年来，物联网（Internet of Things，IoT）技术的快速发展和广泛应用为智能环境监测与管理提供了全新的技术路径。通过部署各类传感器节点，结合无线通信技术和云计算平台，可以实现环境参数的实时感知、数据传输与智能分析。MQTT协议作为物联网领域的事实标准通信协议，具有轻量级、低带宽占用和支持QoS等优势，特别适用于资源受限的嵌入式设备场景。同时，Qt桌面应用开发技术与ECharts Web可视化技术的成熟，为构建功能完善、交互友好的监测管理平台奠定了技术基础。
[161] 因此，本文基于物联网技术，设计并实现了一套面向灾后临时安置点的智慧水电管理与环境监测系统。系统集成了温度、湿度、PM2.5、空气质量、用电电流和水流量等多类环境参数的实时监测功能，并具备智能调控和远程控制能力，对于提升安置点管理的信息化水平、保障受灾群众基本生活安全具有重要的理论意义和实际应用价值。
[162] 1.2 国内外研究现状
[163] 1.2.1 物联网环境监测技术研究现状
[164] 物联网技术在环境监测领域的应用研究已取得丰硕成果。陈超等[1]面向应急安置点环境评估需求，研究了安置点空气质量与健康风险评估方法，强调了实时监测在应急管理中的重要性。何宗军等[2]系统分析了智慧城市框架下的智慧应急响应体系，指出物联网感知网络在应急管理中的核心支撑作用。在无线传感器网络方面，马志新等[3]系统总结了无线传感器网络的关键技术与应用案例，为多节点协同感知提供了技术参考。刘建国等[13]研究了基于STM32的智能环境监测系统设计方法，验证了STM32在环境监测领域的适用性。
[165] 在国际上，OASIS组织发布的MQTT协议[4]已成为物联网数据传输的事实标准。该协议基于发布/订阅模式，具有轻量级、低带宽占用、支持QoS等优势。陈伟等[14]深入研究了MQTT协议在远程监测系统中的应用，验证了其在工业物联网场景下的可靠性。STMicroelectronics公司[5]推出的STM32系列微控制器凭借其高性能、低功耗和丰富的外设资源，已成为嵌入式物联网终端的首选方案之一。Espressif Systems公司[6]的ESP32芯片则集成了WiFi和蓝牙功能，黄志强等[15]设计了基于ESP32的WiFi物联网网关方案，为边缘网关设备提供了理想的解决方案。Atzori等[20]对物联网技术进行了全面综述，系统梳理了物联网的体系架构和关键技术。Yassein等[21]对比分析了物联网应用层协议，为MQTT在资源受限设备上的应用提供了重要参考。
[166] 1.2.2 智慧水电管理研究现状
[167] 李文杰等[7]深入研究了智慧应急与智慧消防协同发展路径，指出水电安全监测是应急管理信息化建设的重要组成部分。赵文静等[8]探讨了一种面向应急响应场景的边缘资源协同架构，为"云、边、端"协同的系统设计提供了参考。张明等[9]研究了基于Qt的监测系统上位机设计与实现方法，验证了Qt在工业监测领域的适用性。孙浩然等[17]研究了基于Qt和MQTT的物联网监控系统设计，为本系统的桌面应用实现提供了直接参考。中国信息通信研究院[10]发布的物联网平台研究报告指出，物联网平台正在向设备管理、数据分析与应用使能三位一体的方向发展。在Web可视化方面，刘晓东等[18]研究了ECharts在数据可视化大屏中的应用，为系统的Web大屏实现提供了技术支撑。周涛等[16]设计了面向智慧园区的多参数环境监测系统，其多传感器融合方案具有重要借鉴意义。在安置点管理领域，赵志强[19]对灾后临时安置点规划与管理进行了系统研究，为本系统的应用场景分析提供了理论依据。
[168] 综合国内外研究现状可以看出，物联网环境监测技术已经较为成熟，但在灾后临时安置点这一特定场景下的水电管理与环境监测系统研究仍相对不足。现有研究多聚焦于单一环境参数的监测或通用物联网平台，缺乏面向安置点实际需求的一体化解决方案。本研究在上述工作基础上，针对灾后安置点的特殊需求，设计并实现了一套集环境感知、数据传输、智能预警与远程控制于一体的智慧水电管理与环境监测系统。
[169] 1.3 主要研究内容与章节安排
[170] 本文围绕灾后临时安置点智慧水电管理与环境监测系统的设计与实现，主要研究内容包括：（1）系统需求分析，明确安置点管理中的功能与非功能需求；（2）系统总体设计，包括技术选型、系统架构、硬件方案和软件方案；（3）系统详细设计与实现，涵盖STM32终端、ESP32网关、Qt桌面应用和Web大屏的完整开发；（4）系统测试与验证，通过实际运行数据验证系统的有效性和可靠性。

[173] 2.1 功能需求分析
[174] 2.1.1 感知层功能需求
[175] 感知层是系统的基础数据来源，其核心功能需求包括：（1）温湿度采集：采用DHT11数字温湿度传感器，温度测量范围0~50°C（精度±2°C），湿度测量范围20~90%RH（精度±5%RH），采样周期1秒，通过单总线协议与STM32通信；（2）PM2.5浓度采集：采用GP2Y1014AU0F光学粉尘传感器，通过脉冲LED驱动（10ms周期，占空比约0.32ms）与ADC采样实现PM2.5浓度检测，LED点亮后约0.28ms处读取电压值；（3）空气质量采集：采用MQ-135气体传感器，通过模拟量输出检测NH₃、CO₂、苯等有害气体浓度，采用16次硬件平均滤波与20次基线校准；（4）用电电流采集：采用ACS712ELCTR-05B霍尔电流传感器，量程±5A，灵敏度185mV/A，通过ADC通道0（PA0）采样，采用64次过采样与一阶低通数字滤波；（5）水流量采集：采用霍尔水流传感器，基于脉冲计数实现瞬时流量与累计流量计算；（6）OLED本地显示：采用0.96英寸SSD1306 OLED显示屏（128×64像素，I²C接口），本地轮询显示各传感器实时数据。
[176] 2.1.2 执行层功能需求
[177] 执行层负责根据环境参数实施智能调控，主要功能包括：（1）舵机控制：采用SG90舵机，通过定时器PWM通道输出控制信号（周期20ms，占空比0.5~2.5ms对应0°~180°），根据温湿度阈值自动调节开窗角度，实现通风与加湿控制；（2）风扇控制：通过MOS管驱动直流风扇，在高温（>30°C）或高湿（>75%RH）条件下自动开启散热/除湿；（3）蜂鸣器报警：当PM2.5浓度超过重度污染阈值时，驱动有源蜂鸣器发出间断式报警音，报警节奏为"120ms导通-220ms断开-120ms导通-220ms断开-120ms导通-1000ms间隔"循环；（4）RGB指示灯：通过红、绿、黄三色LED指示系统运行状态，正常为绿色，预警为黄色，报警为红色。
[178] 2.1.3 边缘网关功能需求
[179] 边缘网关承担数据汇聚与云端传输的核心角色，功能需求包括：（1）通过UART接口（115200bps，8N1）接收STM32上报的传感器数据帧；（2）进行数据校验和与协议转换，将二进制数据帧解析并重组为JSON格式；（3）接入WiFi网络，通过MQTT over WebSocket协议将数据发布至巴法云平台（wss://bemfa.com:9504/wss）；（4）执行本地阈值判断，在WiFi中断等异常情况下实现边缘侧快速自主响应；（5）接收云端下发的控制指令并转发至STM32，实现远程控制。
[180] 2.1.4 上位机平台功能需求
[181] 上位机桌面应用部署于Windows PC端，是系统的主要人机交互界面，功能需求包括：（1）用户管理：包括用户注册、登录、角色权限管理（管理员/普通用户），支持切换账号功能；（2）实时监控：以卡片形式展示温度、湿度、PM2.5、AQI（空气质量指数）、电流、流量等实时数据，并通过折线图展示变化趋势，每个参数卡片配有三色状态指示灯；（3）历史查询：按1小时、24小时、7天时间范围检索历史数据，以柱状图或折线图展示，支持XLSX格式文件导出；（4）报警管理：实时显示报警信息，表格记录报警时间、传感器类型、报警内容，支持报警去重；（5）远程控制：支持对终端设备的远程操作，包括手动控制风扇开关、舵机角度设置、蜂鸣器开关等，并记录操作日志；（6）设备管理：支持设备的添加、删除、信息查看与固件版本管理。
[182] 2.2 非功能需求分析
[183] （1）实时性：传感器数据采集周期不超过1秒，数据从终端到上位机的传输延迟不超过5秒，报警响应时间不超过3秒。（2）可靠性：系统应支持7×24小时连续运行，平均无故障时间（MTBF）不低于720小时；数据采集丢失率不超过0.1%。（3）可扩展性：系统应支持不少于6个传感器节点的同时接入，支持后续传感器类型和数量的扩展。（4）安全性：系统实现用户认证与权限控制，关键操作记录操作日志，数据库文件具备访问保护。（5）易用性：界面设计简洁直观，具有明确的操作提示和状态反馈，支持鼠标和键盘操作。
[184] 2.3 系统约束与接口需求
[185] （1）硬件约束：终端节点采用STM32F103C8T6微控制器（ARM Cortex-M3内核，主频72MHz，64KB SRAM，128KB Flash）；边缘网关采用ESP32芯片（双核Xtensa LX6，主频240MHz，集成WiFi 802.11b/g/n和蓝牙4.2）。（2）通信约束：终端与网关之间采用UART串口通信（波特率115200bps，8位数据位，1位停止位，无校验）；网关与云端之间采用WiFi + MQTT over WebSocket Secure协议，MQTT服务器为巴法云平台（地址wss://bemfa.com:9504/wss），MQTT协议版本3.1.1，QoS等级1。（3）软件约束：上位机基于Qt 6.11框架（C++语言，MinGW 11.2编译器）开发，集成QtCharts 6.11模块和QMqttClient 6.11模块；Web大屏使用纯前端技术（HTML5+CSS3+JavaScript+ECharts 5.5.1+MQTT.js 5.0+）。（4）数据约束：本地数据库采用SQLite 3，数据库文件固定存储于D:\System_UI_Data\system_ui.sqlite，初始建表脚本随桌面应用首次启动自动执行。

[223] 4.1 硬件详细设计与实现
[224] 4.1.1 温湿度采集模块
[225] 温湿度采集采用DHT11数字温湿度传感器，通过单总线协议与STM32进行数据通信。DHT11的数据线连接至STM32的GPIOB Pin13，通过软件模拟单总线时序实现读写操作，需配置为开漏输出并外接4.7kΩ上拉电阻。完整的通信过程包括：主机（STM32）发送启动信号（拉低总线至少18ms，然后拉高20~40µs）→DHT11响应信号（拉低80µs作为应答，再拉高80µs准备数据）→DHT11连续发送40位数据（高位先出，包括湿度整数8bit、湿度小数8bit、温度整数8bit、温度小数8bit和校验和8bit）。每一位数据的读取通过检测总线电平持续时间判断：26~28µs的低电平起始位后，若高电平持续约70µs表示数据位"1"，约26~28µs表示数据位"0"。STM32在主循环中以1秒为周期调用DHT11_Read_Data函数，数据校验采用累加和校验方式（前四个字节之和等于校验字节）。当校验通过后，提取温度值和湿度值，参与后续的阈值判断、OLED显示和MQTT上传。若连续5次读取失败，系统判定传感器离线并触发离线告警。STM32主程序的完整数据采集与处理流程如图4-1所示。

[230] 4.1.2 PM2.5采集模块
[231] PM2.5浓度采集采用夏普GP2Y1014AU0F光学粉尘传感器。该传感器内部集成红外发光二极管和光电晶体管，通过检测空气中悬浮颗粒物对红外光的散射强度来计算粉尘浓度。GP2Y1014AU0F是GP2Y1010AU0F的升级型号，具有更宽的动态范围和更好的线性度。传感器的正常工作需配合周期性脉冲驱动：控制LED引脚以10ms为周期（占空比约3.2%）驱动内部LED发射红外光，在LED点亮后约0.28ms处通过ADC读取输出电压（Vo引脚），因为此时散射光信号最强。STM32通过GPIO控制LED驱动时序，ADC采集电压值经过10次基线采样校准和数字滤波后，通过标定曲线转换为粉尘密度（µg/m³）。转换公式为：dustDensity = (adcVoltage - baselineVoltage) × 5000 / 1024，其中baselineVoltage为洁净空气中的参考电压。经校准后测量范围为0~500µg/m³，分辨率约为1µg/m³。
[232] 4.1.3 电流采集模块
[233] 用电电流采集采用ACS712ELCTR-05B霍尔效应电流传感器芯片。该芯片基于霍尔效应原理，当被测电流流过芯片内部的铜导电路径时，产生的磁场被霍尔元件感应并转换为线性电压输出。5A量程版本的灵敏度为185mV/A，在无负载条件下输出零点电压约为2.5V（VCC=5V供电时）。STM32通过ADC通道0（PA0）采集传感器的电压输出，采用64次硬件过采样取均值的方式提高测量精度，有效分辨率可达12位以上。软件还实现了一阶低通数字滤波器进行平滑处理：filteredValue = (1 - α) × filteredValue_prev + α × rawValue。为提高响应速度同时兼顾稳定性，滤波系数分为上升沿系数α_rise=0.45（快速跟踪电流上升）和下降沿系数α_fall=0.18（缓慢回落防抖）。电流实际值计算公式为：current_A = (filteredVoltage - 2.5) / 0.185。当检测到的电流绝对值小于50mA的死区阈值时，视为零电流以消除零漂影响。电流数据用于功率计算（P=UI，假设电压为220V）和过载保护判断。
[234] 4.1.4 执行器控制模块
[235] 系统执行器包括SG90舵机、直流风扇、有源蜂鸣器和RGB三色LED，各执行器的控制逻辑如下。
[236] SG90舵机通过STM32定时器2的PWM通道1（PA0）进行控制，PWM周期为20ms（50Hz），占空比在0.5ms~2.5ms范围内对应0°~180°的转动角度。系统预设了三个角度值：SERVO_HOME=0°（初始位置）、SERVO_WIN_OPEN=45°（开窗通风）、SERVO_HUMI_OPEN=90°（加湿位置）。温湿度联动控制逻辑为：当温度超过32°C时舵机转至开窗位促进散热；当湿度低于30%时转至加湿位。直流风扇通过N沟道MOS管（IRF520）驱动电路由GPIO控制启停，高电平有效。风扇自动控制条件为：温度超过30°C或PM2.5超过75µg/m³或湿度超过75%RH。有源蜂鸣器通过NPN三极管（S8050）驱动，在PM2.5超过150µg/m³（重度污染）时按"120ms导通-220ms断开-120ms导通-220ms断开-120ms导通-1000ms间隔"的模式循环发声。RGB三色LED通过三路GPIO控制，分别串联220Ω限流电阻。系统上电初始化时所有GPIO输出低电平。三级指示逻辑为：正常时绿灯常亮（GPIO高电平驱动），预警时黄灯常亮（红+绿同时亮），报警时红灯常亮。
[237] 4.2 边缘网关实现
[238] 边缘网关由ESP32模块实现，作为STM32终端与云平台之间的数据桥梁。ESP32通过UART接口以115200bps波特率接收STM32发送的数据帧，完成格式校验后通过WiFi以MQTT over WebSocket协议上报至巴法云平台。ESP32固件的核心功能模块包括：（1）UART中断接收处理：配置UART2（RX=GPIO16，TX=GPIO17）接收来自STM32的传感器数据帧，数据帧格式为帧头（0xAA）+数据长度+传感器数据+CRC校验+帧尾（0x55），接收采用环形缓冲区+状态机解析方式；（2）WiFi网络初始化：调用WiFi.begin(ssid, password)接入指定WiFi热点，设置自动重连和静态IP（可选），连接超时时间15秒；（3）MQTT客户端管理：采用PubSubClient库建立MQTT over WebSocket连接，服务器地址为wss://bemfa.com:9504/wss，客户端ID使用用户私钥，心跳保活间隔60秒；（4）传感器数据封装：将解析后的传感器数值封装为JSON格式（{\"temp\":25.5,\"humi\":60.2,...}），调用client.publish(topic, payload)发布；（5）控制指令接收与转发：通过MQTT订阅控制主题，收到指令后解析JSON，通过UART转发至STM32执行。ESP32还实现了本地阈值缓存和WiFi离线时的本地自主判断机制，在云端通信中断时仍可独立完成阈值比较和GPIO触发，有效降低对云端回传的依赖和响应延迟。系统的完整MQTT通信时序如图4-2所示，展示了从传感器数据采集到上位机展示、从上位机下发指令到终端执行器响应的完整消息传递过程。

[242] 4.3 桌面应用详细实现
[243] 4.3.1 用户认证模块
[244] 用户认证模块实现了用户注册、登录和角色权限管理功能。系统采用SQLite数据库存储用户信息，users表包含username（唯一）、password（明文存储，实际部署应使用哈希加密）、role、phone、email等字段。登录界面（LoginDialog）提供账号和密码输入框以及角色选择下拉框，支持"记住密码"功能（通过QSettings保存凭据）。认证服务（AuthService）封装了注册、登录验证、密码更新和会话管理等核心逻辑。系统支持管理员（admin）和普通用户（user）两种角色：管理员具有设备配置、用户管理、远程控制全部权限；普通用户仅具备数据查看和基本操作权限。登录验证成功后创建主界面（MainWindow）实例，并传递用户名和角色参数。右上角用户信息区域提供切换账号和账户编辑功能，切换账号时断开MQTT连接并返回登录界面。用户登录的完整流程如图4-3所示。
[247] 图4-3 用户登录流程图
[249] 4.3.2 实时监控模块
[250] 实时监控模块以卡片形式展示六项传感器参数（温度、湿度、PM2.5、AQI、电流、水流量）。每个参数卡片由QLabel显示传感器数值（大字体，36px）和单位、状态指示灯（QLabel设置圆形样式，16×16px，三色：绿#4CAF50/黄#FF9800/红#F44336）和状态文字标签。状态判断通过MetricTier枚举（Normal/Warning/Danger）进行三级分类，各参数的具体阈值配置如下：温度Normal≤30°C→Warning≤35°C→Danger>35°C；湿度Normal≤50%→Warning≤75%→Danger>75%；PM2.5和AQI Normal≤75→Warning≤100→Danger>100；电流Normal≤300mA→Warning≤500mA→Danger>500mA；水流量Normal≥3L/min→Warning≥1L/min→Danger<1L/min（流量越低越危险）。实时数据通过MQTT消息接收，MainWindow::updateData函数在收到新数据时自动更新卡片数值、指示灯颜色和状态标签，同时将数据追加到趋势折线图序列中。监控首页还包含一个多曲线趋势图（QChart/QLineSeries），显示最近20个采样周期的温湿度变化趋势。
[251] 4.3.3 MQTT通信模块
[252] MQTT通信模块基于Qt 6.11的QMqttClient类实现。在MainWindow初始化时调用initMqtt函数建立与巴法云平台的WebSocket MQTT连接。连接参数包括服务器地址（wss://bemfa.com:9504/wss）、客户端ID（从配置文件中读取的用户私钥）和订阅主题列表。Mqtt封装类提供了三个核心接口方法：connectWithKey(host, port, key)建立加密WebSocket连接；subscribeTopic(topic)订阅指定主题，QoS等级设为1（至少一次）；publishText(topic, text)发布文本消息至指定主题，QoS等级设为1。消息接收采用Qt信号-槽机制：当QMqttClient::messageReceived信号触发时，Mqtt对象转发为textMessageReceived(topic, payload)信号，MainWindow连接此信号并将数据传递给updateData函数进行JSON解析和数据分发。网络中断时客户端自动按5秒周期尝试重连，重连成功时自动重新订阅所有已注册主题。为实现双向通信，系统维护了两个主题：数据上报主题（subscribeTopic用于接收数据）和控制下发主题（publishText用于发送指令）。
[253] 4.3.4 历史数据与报警管理模块
[254] 历史数据模块支持按1小时、24小时和7天三个时间范围查询传感器历史记录。查询时通过DatabaseManager::queryRecentData方法从sensor_samples表中检索数据，参数limit限制返回记录数，参数since指定起始时间。查询结果以QStackedBarSeries柱状图形式展示在QChart中，X轴（QBarCategoryAxis）为时间标签，Y轴（QValueAxis）为参数值，不同参数以不同颜色的QBarSet区分。历史数据支持导出为原生XLSX格式文件，导出功能使用QXlsx或QAxObject实现，生成的文件包含数据表头、数据行、统计行、合并单元格和列宽设置。
[255] 报警管理模块记录所有超限事件的详细信息。当参数超过预警或报警阈值时，系统调用DatabaseManager::insertAlarmInfo函数将报警时间、传感器名称和报警内容写入alarm_info表。系统实现了报警去重机制：同一传感器的同一超标状态不会重复记录报警条目，只有当超标程度从预警升级为报警或数值恢复正常时，才新增报警记录。报警信息以QTableWidget表格形式展示在报警页面上，包含报警时间、传感器名称和报警内容三列，表格按时间降序排列，最新报警显示在首行。报警发生时，系统同时更新实时监控页面的状态指示和报警计数器。
[256] 4.4 Web大屏实现
[257] Web大屏展示系统采用纯前端技术栈实现，基于ECharts 5.5.1图表库和MQTT.js 5.0+库。页面采用深色科技风主题（背景色#1a1a2e），整体布局采用CSS Grid分三列设计：左侧为6个ECharts仪表盘（Gauge图）分别展示温度、湿度、PM2.5、AQI、电流和流量的实时数值，每个仪表盘采用三级色带（绿#4CAF50-橙#FF9800-红#F44336）指示数据所处区间，指针颜色随数据状态自动切换；中间上半部分为温湿度与PM2.5/AQI多系列折线图（line chart），显示最近60个采样点的趋势变化；中间下半部分为用电电流和用水流量的实时曲线；右侧为报警信息滚动面板（marquee），按时间倒序显示最新报警条目，新报警以高亮动画弹出。Web页面通过MQTT.js建立WebSocket连接（wss://bemfa.com:9504/wss），直接订阅巴法云平台的MQTT主题，与桌面应用共享同一数据源。页面实现了历史数据本地缓存机制：使用localStorage存储最近1440个数据点（约1440分钟，即24小时），在网络断线重连后可从缓存回放历史数据，确保展示连续性。页面自适应分辨率，在1920×1080以上分辨率下满屏展示，并向下兼容1366×768。
[258] 4.5 报警与预警机制
[259] 系统实现了一套完整的三级报警与预警机制。图4-5展示了系统软件功能结构，其中报警管理模块作为上位机管理系统的重要子系统，实现了从数据采集到报警响应的完整流程。
[262] 图4-5 系统功能结构图
[264] 三级报警机制的工作原理如图4-6所示。各环境参数划分为三个等级：（1）正常等级（Normal）：各项参数在安全范围内，状态指示灯为绿色（GPIO输出控制绿灯常亮），系统正常运行，不触发任何报警动作；（2）预警等级（Warning/Attention）：参数达到关注阈值但尚未超过危险阈值，状态指示灯切换为黄色（红+绿同时亮），记录预警日志到alarm_info表，但不触发声光报警，桌面应用和Web大屏黄色高亮提示；（3）报警等级（Danger/Alarm）：参数超过危险阈值，状态指示灯切换为红色，RGB LED红灯常亮，蜂鸣器按预定义节奏发出报警音，同时向桌面应用和Web大屏推送报警信息，报警记录写入alarm_info表持久化保存。
[267] 图4-6 三级报警机制示意图
[269] 报警判断函数（evaluateMetricTier）分别对温度、湿度、PM2.5/AQI、电流和流量六项参数进行独立的分级判定。正常→预警和预警→报警的转换均采用施密特迟滞比较器思想，防止在阈值附近频繁抖动：当参数从正常上升至预警阈值时触发预警，但需回落至正常阈值以下5%才恢复至正常状态，预警→报警同理。系统整体报警响应链路延迟不超过3秒（从传感器采集到上位机显示），满足实时性需求。报警与预警机制的实现，使得安置点管理人员能够第一时间发现异常并采取措施，有效提升了系统的安全保障能力。
[270] 第5章 系统测试与验证
[271] 5.1 测试方案
[272] 测试分为三个阶段：（1）单元测试：对各传感器模块、通信模块和功能模块进行独立测试，验证各模块功能的正确性；（2）集成测试：将各模块组合为完整系统，验证模块间的协同工作和数据流通，重点测试STM32↔ESP32的UART通信和MQTT端到端数据传输；（3）系统测试：全系统运行状态下模拟实际应用场景，验证综合性能指标，包括数据准确性、通信可靠性、报警响应时间、系统稳定性和长时间运行鲁棒性。测试环境包括：STM32F103C8T6核心板（含最小系统电路）、ESP32-WROOM-32开发板、各传感器模块和执行器模块、Windows 11 Pro PC（运行Qt桌面应用，CPU i7-12700，RAM 32GB）、Chrome浏览器（运行Web大屏）、TP-Link AX3000无线路由器（2.4GHz频段）。
[273] 5.2 模块测试
[274] 对各传感器进行数据采集准确性测试。DHT11温湿度传感器在室温环境下连续采集100组数据，温度测量范围22.0~25.3°C，与标准水银温度计比对误差在±1.5°C范围内，湿度测量范围45~62%RH，误差在±4%RH范围内，符合产品规格书指标。MQ-135空气质量传感器在洁净空气中PPM值波动幅度不超过±3%，在靠近酒精蒸汽时响应时间约3秒，恢复时间约30秒。ACS712电流传感器在50mA~2000mA电流范围内通过可调电阻箱进行线性度测试，经64次过采样和低通滤波后测量精度达到±10mA，线性度R²=0.997。GP2Y1014AU0F粉尘传感器在室内环境下能够稳定检测PM2.5浓度变化，在点燃蚊香模拟污染场景中，浓度读数从15µg/m³上升至200µg/m³，响应灵敏。水流传感器在稳定水流条件下（1~10L/min），脉冲频率与流量呈线性关系，R²=0.993。OLED显示屏在各传感器数据刷新时显示正常，无明显闪烁或花屏。
[275] 5.3 集成测试与结果分析
[276] 在全系统集成运行环境下进行了连续72小时的稳定性测试。测试期间系统运行稳定，未发生死机或数据采集中断现象。传感器数据采集周期稳定在1秒（通过示波器测量DHT11数据总线波形确认），MQTT数据上传周期平均约1.5秒（含WiFi传输延迟），最长不超过5秒。报警功能测试结果表明：当PM2.5浓度超过150µg/m³时，蜂鸣器在1秒内发出报警音，桌面应用和Web大屏在2秒内同步显示报警信息，颜色指示同步切换为红色。在模拟温湿度变化场景中（使用电吹风加热），温度从25°C上升至35°C时，风扇和舵机在阈值触发后约1.5秒内完成动作响应。系统运行期间共采集传感器数据约259200组（72h×3600s/h），数据完整率100%（通过解析日志文件统计）。桌面应用实时监控页面刷新流畅，MQTT消息处理未出现明显积压，折线图更新帧率约1fps。Web大屏在Chrome 120+、Edge 120+、Firefox 121+等主流浏览器上均正常显示，页面加载时间不超过2秒，MQTT消息至仪表盘更新延迟约1秒。SQLite数据库文件在72小时运行后大小约4.2MB，查询效率未出现明显下降。
[277] 5.4 测试总结与优化方向
[278] 通过多层次的系统测试，验证了本系统在功能完整性、数据准确性、通信可靠性和报警响应及时性等方面均达到了设计目标。后续可进一步优化的方向包括：（1）传感器长期稳定性需在实际安置点环境中进行至少1个月的连续运行验证，以评估传感器漂移和老化影响；（2）可引入自适应阈值算法（如动态阈值+机器学习），根据历史数据自动调整各参数的报警阈值，降低误报率和漏报率；（3）移动端APP（Android/iOS）可作为后续扩展方向，基于Flutter或React Native开发，进一步提升系统的便携性和管理可达性；（4）多安置点组网监控功能，支持上级应急管理部门集中查看多个安置点的运行状态，实现统一调度和资源优化配置。
[279] 结论
[280] 本文围绕灾后临时安置点的智慧水电管理与环境监测需求，设计并实现了一套基于物联网技术的综合监测系统。系统采用"云、边、端"三层协同架构，以STM32F103C8T6嵌入式终端实现多源传感器数据采集与执行器控制，以ESP32边缘网关实现WiFi接入与MQTT通信，以Qt桌面应用提供实时监控、历史查询、报警管理和远程控制功能，以Web大屏实现数据可视化展示。
[281] 系统综合运用DHT11、GP2Y1014AU0F、MQ-135、ACS712ELCTR-05B和霍尔水流传感器，实现了对安置点环境参数的全面实时感知。系统集成的智能调控机制能够根据环境参数变化自动控制SG90舵机、直流风扇、有源蜂鸣器和RGB LED等执行器。SQLite数据库提供的本地持久化存储机制，配合三级报警与预警体系，确保了数据完整性和异常响应及时性。
[282] 测试结果表明，系统运行稳定可靠，传感器数据采集准确（温度±1.5°C、湿度±4%RH、电流±10mA），MQTT通信延迟在1~5秒内，报警响应时间不超过3秒，能够有效满足灾后临时安置点水电管理与环境监测的实际需求。本系统的设计与实现为物联网技术在应急管理领域的应用提供了有益的实践探索，对未来安置点信息化管理水平的提升具有积极的参考价值。
[283] 由于研究时间和实验条件的限制，系统仍存在一些不足之处，包括传感器长期稳定性验证不足、缺少移动端应用支持、未实现多安置点组网监控等。后续工作可从自适应阈值算法、移动端APP开发和多安置点统一管理平台等方向进一步开展研究。

[312] 系统数据库文件位于 D:\System_UI_Data\system_ui.sqlite，各表字段结构如下：
[313] 表A users用户表
[314] CREATE TABLE users (  id INTEGER PRIMARY KEY AUTOINCREMENT,  username TEXT UNIQUE NOT NULL,  password TEXT NOT NULL,  role TEXT DEFAULT 'user',  phone TEXT,  email TEXT,  created_at DATETIME DEFAULT CURRENT_TIMESTAMP);
[315] 表B sensor_samples传感器采样表
[316] CREATE TABLE sensor_samples (  id INTEGER PRIMARY KEY AUTOINCREMENT,  timestamp DATETIME DEFAULT CURRENT_TIMESTAMP,  temperature REAL,  humidity REAL,  pm25 REAL,  air_index REAL,  current_ma REAL,  flow_lmin REAL);
[317] 表C device_info设备信息表
[318] CREATE TABLE device_info (  id INTEGER PRIMARY KEY AUTOINCREMENT,  device_id TEXT UNIQUE NOT NULL,  device_name TEXT,  device_type TEXT,  location TEXT,  firmware_version TEXT,  status TEXT DEFAULT 'offline',  sample_interval_sec INTEGER DEFAULT 60);
[319] 表D alarm_info报警信息表
[320] CREATE TABLE alarm_info (  id INTEGER PRIMARY KEY AUTOINCREMENT,  alarm_time DATETIME DEFAULT CURRENT_TIMESTAMP,  sensor_name TEXT,  alarm_content TEXT,  alarm_level TEXT DEFAULT 'warning');
[321] 表E remote_exec_logs远程执行日志表
[322] CREATE TABLE remote_exec_logs (  id INTEGER PRIMARY KEY AUTOINCREMENT,  device_id TEXT,  command_text TEXT,  result_text TEXT,  execute_time DATETIME DEFAULT CURRENT_TIMESTAMP);
